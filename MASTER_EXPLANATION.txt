1. THE ELEVATOR PITCH (1 MINUTE)
--------------------------------------------------------------------------------
"Most game-playing AI agents rely on heavy, expensive generative LLMs like GPT-4
that cost dollars per game, lag by several seconds, and inevitably hallucinate
invalid moves. ProgrammablePros takes an entirely different architectural route:
we engineered an autonomous decision layer powered by Laya, a lightweight,
open-weight calibrated probability model.

Instead of asking an AI 'What should I do next?', our bot transforms the game
state into typed binary hypotheses, queries Laya for pure mathematical success
probabilities in milliseconds, and selects moves using a rigorous Expected Value
(EV) risk-reward engine. The result is a lightning-fast, zero-hallucination,
failure-adaptive bot that plays with institutional-grade auditability across both
1-D navigation and complex 2-D multi-hazard heist environments."


2. SUPPORTED GAME ENVIRONMENTS
--------------------------------------------------------------------------------
Our decision layer drives two distinct game environments via a unified registry:

1. 1-D Grid Navigator (mock_game.py):
   - Grid: Linear corridor from position 0 to 10 (30 steps max)
   - Goal: Reach goal position 10
   - Legal Actions: LEFT, RIGHT

2. Vault Runner 2-D Heist (vault_game.py):
   - Grid: 8x8 procedural floor (40 steps max)
   - Hazards: Guard patrol (G, -30 penalty), Lasers (L, -5 penalty), Traps (T, -8 penalty),
     Hidden Walls (H), Sprint Wall Crash (-15 penalty)
   - Objective: Multi-stage: collect Key (K) first, then unlock Exit (E)
   - Legal Actions: UP, DOWN, LEFT, RIGHT, WAIT, SPRINT (2-tile leap)


3. HOW THE BOT WORKS: THE 9-STEP PIPELINE
--------------------------------------------------------------------------------
The bot operates on a continuous, deterministic Sense-Think-Act-Learn loop
orchestrated in agent_orchestrator.py and main.py:

  [ Sense ]        -> Game Server State (positions, steps, boundaries, visible grid)
      |
  [ Compress ]     -> Feature Engineering & Egocentric POV:
                      - 1-D: 60-character vector string
                      - 2-D Vault: <= 120 chars, zero hidden wall leakage
                      - Egocentric POV (EgocentricCompressor): AHEAD/LEFT/RIGHT/BEHIND,
                        8-point bearings (N, NE, E), Manhattan dists, resources, failure history
      |
  [ Reason ]       -> SubgoalManager: arbitrates active tactical target (RETREAT -> KEY -> EXIT -> EXPLORE)
                      HypothesisEngine: generates 4 typed questions per legal action (is_legal,
                      toward_subgoal, is_dangerous, is_novel) + anchor sanity probes
      |
  [ Query ]        -> Query Laya for calibrated probabilities on all hypotheses
      |
  [ Calibrate ]    -> CalibrationEngine: applies Platt scaling to map raw likelihoods to calibrated probabilities
      |
  [ Decide ]       -> AdvancedEVCalculator: computes multi-objective risk-adjusted Expected Value (EV) argmax
      |
  [ Act & Audit ]  -> Dispatch move to game API + DecisionLogger appends record to decision_log.jsonl with flush
      |
  [ Learn ]        -> WorldMemory: if action fails to alter coordinates, mark target as WALL.
                      Record empirical outcomes ((x,y), action) and dynamic prompt warnings.


4. DEEP DIVE: THE CORE STRATEGIES & UPGRADES
--------------------------------------------------------------------------------

STRATEGY 1: STATE COMPRESSION & FEATURE ENGINEERING
* What it is:
  Raw game states arrive as multi-layered, nested JSON dictionaries cluttered with
  metadata. We extract only mathematical invariants:
  - 1-D: "pos=3, goal=10, dist=7, steps=27"
  - 2-D Vault: "pos=(2,2) obj=KEY obj_dist=3 keys=0 steps_left=35 laser_adj=NONE guard_dist=4 guard_dir=UP facing=RIGHT"
* Why it matters:
  Small models have limited parameter capacity. Flooding them with 50 lines of JSON
  dilutes attention weights. Dense feature engineering presents high signal-to-noise
  data, ensuring Laya dedicates its capacity solely to spatial calculation.
* Concrete Example:
  Instead of feeding 600 bytes of raw JSON containing grid arrays, styling, and
  status strings, Laya receives a <=120-character dense vector where distance,
  adjacency, and decay are pre-calculated, preventing arithmetic miscalculations.

STRATEGY 2: HYPOTHESIS-DRIVEN "TYPED QUESTIONS"
* What it is:
  Laya is an open-weight model specialized in probability calibration, not open chat.
  Instead of prompting "Where should I move?", formulate_questions() poses a closed,
  testable binary hypothesis:
  "Context: {compressed_state}. Hypothesis: Executing action '{action}' will
  successfully progress toward {goal_phrase}. What is the calibrated probability
  (0.0 to 1.0) that this hypothesis is true?"
* Dynamic Goal Switching:
  - Phase 1 (Keys = 0): "the KEY"
  - Phase 2 (Keys = 1): "the EXIT without being caught or hitting a hazard"
* Why it matters:
  Open-ended questions force models to generate freeform text, leading to parse
  errors, hallucinations, and non-deterministic output. By framing each move as an
  independent hypothesis, we treat Laya as a pure likelihood scoring function,
  directly extracting calibrated P(True) in [0.0, 1.0].

STRATEGY 3: EXPECTED VALUE (EV) DECISION MAKING
* What it is:
  A probability is only half of a decision; the other half is the payoff matrix:
    EV = (P_success * Reward) - ((1.0 - P_success) * Penalty)
  In Vault Runner, get_action_risk() calculates environment-specific downside:
  - Guard proximity: Penalty = 30.0
  - Laser entry: Penalty = 15.0
  - Sprint wall crash: Penalty = 15.0
  - Waiting safely: Penalty = 1.0
* Why it matters:
  Novice teams implement an argmax(probabilities) policy. But in game environments
  where certain actions carry asymmetric penalties, choosing a move with a high raw
  probability and extreme downside is a losing strategy.
* Concrete Benchmark Proof (Vault Runner Test 4):
  Suppose action SPRINT has raw P = 0.72 (Reward = +8.0, Penalty = -15.0 due to a wall).
    EV(SPRINT) = (0.72 * 8.0) - (0.28 * 15.0) = +1.56
  Meanwhile, DOWN has P = 0.70 (Reward = +10.0, Penalty = -5.0):
    EV(DOWN) = (0.70 * 10.0) - (0.30 * 5.0) = +5.50
  An argmax bot greedily chooses SPRINT (0.72 > 0.70) and crashes; our EV bot
  chooses DOWN (+5.50 > +1.56) and cleanly preserves equity.

STRATEGY 4: FAILURE-ADAPTIVE PROMPTING (SHORT-TERM MEMORY)
* What it is:
  A bounded short-term memory ring buffer (recent_outcomes, tracking last 3 turns).
  If an action fails to reduce distance to goal or hits an invisible hidden wall,
  the transition is logged. On the next turn, the hypothesis prompt appends:
  "WARNING: In the previous turn, taking action '{action}' resulted in no progress.
  Adjust probability accordingly."
* Why it matters:
  Stateless bots suffer from oscillatory trap loops: facing a hidden obstacle or
  locked barrier, a stateless bot repeatedly selects the same move turn after turn
  until it times out. Our adaptive memory breaks loops on turn N+1.
* Concrete Example from Live Vault Run:
  At position (2, 2), moving RIGHT hits a hidden wall at (3, 2).
  - Turn 30: Bot picks RIGHT. Result: player remains at (2, 2), hidden wall logged.
  - Turn 31: Prompt appends WARNING. Laya incorporates negative prior and drops
    P(RIGHT) from 80.3% -> 10.0%.
  - Immediate Impact: EV(RIGHT) plunges from +7.04 -> -3.50. The bot immediately
    pivots to WAIT (EV = -0.11) and UP (EV = +1.04), clearing the obstacle.

STRATEGY 5: PERCEPTION LAYER (WORLD MEMORY & EGOCENTRIC POV)
* What it is:
  1. WorldMemory (world_memory.py): Persistent spatial map of WALL, FREE, UNKNOWN,
     entry visit decay, and empirical outcome rates ((x,y), action) -> [successes, attempts].
     Automatically infers walls when coordinate changes fail.
  2. EgocentricCompressor (egocentric_compressor.py): Converts global coordinates
     into an agent-centric frame:
     POV: agent at (x,y), facing [DIR]
     LOCAL: AHEAD: [status], LEFT: [status], RIGHT: [status], BEHIND: [status]
     OBJECTIVES: KEY(bearing=SE, dist=4), EXIT(bearing=SE, dist=13 [LOCKED-NEEDS-KEY])
     RESOURCES: health=X, ammo=Y, keys=K, steps_left=Z
     HISTORY: action 'UP' at (x,y) failed (hit wall)

STRATEGY 6: REASONING LAYER (SUBGOALS & 4-WAY HYPOTHESES)
* What it is:
  1. SubgoalManager (subgoal_manager.py): Hierarchical goal arbitration with
     strict priority: RETREAT -> KEY -> EXIT -> EXPLORE.
  2. HypothesisEngine (hypothesis_engine.py): Formulates 4 typed scientific questions
     per legal action: is_legal, toward_subgoal, is_dangerous, is_novel.
  3. Anchor Probes: Injects ground-truth sanity check questions (e.g. wall legality is 0.0)
     to monitor model calibration drift in real time.

STRATEGY 7: ORCHESTRATION & DECISION ENGINE
* What it is:
  1. AgentOrchestrator (agent_orchestrator.py): Master coordinator executing the full 9-step
     decision pipeline end-to-end.
  2. AdvancedEVCalculator (advanced_ev_calculator.py): Synthesizes legality filters, subgoal utility,
     danger penalties, novelty bonuses, and repeat failure suppression.
  3. CalibrationEngine (calibration_engine.py): Post-hoc Platt scaling and empirical Brier scoring.
  4. DecisionLogger (decision_logger.py): Non-blocking append-only JSONL streaming logger with immediate flushing.

8. TOP 3 ANTICIPATED JUDGE QUESTIONS & PERFECT ANSWERS
--------------------------------------------------------------------------------
Q1: "Why use a small calibrated probability model like Laya instead of GPT-4o?"
A1: "Generative frontier models have high inference latency (1-3 seconds), cost
     significantly more, and hallucinate unexecutable moves. Laya is purpose-built
     for calibration: it returns mathematically grounded probabilities in tens of
     milliseconds with zero hallucination. Combined with our EV engine, Laya provides
     deterministic, risk-managed control that frontier LLMs cannot replicate at game speed."

Q2: "How does your Expected Value formulation prevent losses when a higher
     probability move is available?"
A2: "Argmax bots always pick the highest probability. But gaming penalties are
     asymmetric. In Vault Runner, sprinting into a wall has 72% success but a -15
     penalty (EV = +1.56). Stepping down has 70% success with standard penalty (EV = +5.50).
     Our EV engine mathematically avoids high-probability 'death traps' and selects
     the move with the highest risk-adjusted mathematical expectation."

Q3: "What happens if the game introduces novel mechanics or invisible obstacles?"
A3: "Our agent uses Feature 4 (Failure-Adaptive Prompting), Feature 5 (WorldMemory),
     Feature 6 (SubgoalManager), and Feature 7 (AgentOrchestrator). When an action
     unexpectedly hits a hidden wall or barrier, the target coordinate is mapped as
     WALL and the transition is logged. On the next tick, the hypothesis prompt
     injects an in-context negative prior informing Laya. This suppresses the
     probability, flips the EV ranking, and forces exploration of alternative trajectories,
     preventing infinite trap loops."
